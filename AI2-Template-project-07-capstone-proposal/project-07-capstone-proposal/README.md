# Project 07 — AI System Design Capstone

> **🛠️ Stack for this lesson** — Google Docs / Figma / Canva / Draw.io · pen-and-paper or digital sketching, then a polished mockup tool.
> 📥 Template: [/learn/ai2/template/project-07-capstone-proposal](/learn/ai2/template/project-07-capstone-proposal)

The AI2 capstone: a written proposal plus UI mockups for an AI system you'd actually want built. No code shipped — but every choice you make (which model, which dataset, which user, which failure mode) is informed by the eight activities and six projects you've finished.

**Time:** 2–3 weeks · **Concept:** Course capstone

---

## What You'll Build

A 5+ page proposal document plus 2–3 polished UI screens. 8 outcome-driven TODOs across three phases:

| Phase | Focus | Outcome |
|-------|-------|---------|
| 1. Research | Problem + solution + objectives | Half-page problem statement, half-page solution, 2–3 SMART objectives |
| 2. System design | Modules + tools + algorithms + users | 3–4 modules with features, complete tool list, 2–3 algorithm justifications, user groups + impact |
| 3. UI prototype | Sketches + mockups | 2–3 sketches reviewed by tutor, then polished mockups in Figma / Canva / Draw.io |

Read the proposal outline, decide what your project is, and write it. The example folder shows shape, not content to copy.

## Run It

There's no script to run — your "running" deliverable is the live Google Doc and the mockup file.

1. Copy the [Google Docs template](https://docs.google.com/document/d/1AXH-KXJDHbWhi7S9ZcWFhzJBdwINYtSUcF23DcrE8bM/edit?usp=share_link) (`File > Make a copy`).
2. Rename to `[Your Name] - AI-2 Final Project Proposal`.
3. Work through `proposal-outline.md` section by section.
4. Sketch UI on paper or Jamboard, then convert to Figma / Canva / Draw.io.

## Verify

Your capstone is done when:

- [ ] Problem statement is half a page, names a specific problem (not "solve climate change"), backed by stats or a real example.
- [ ] Solution has a name, a one-paragraph description, and a list of who uses it.
- [ ] You have 2–3 SMART objectives — Specific, Measurable, Achievable, Relevant, Time-bound.
- [ ] 3–4 modules are listed with name, description, and feature list.
- [ ] Tools section covers every feature — no orphan features without a tool.
- [ ] 2–3 algorithms are listed with a one-sentence justification per algorithm ("YOLOv8 because real-time matters").
- [ ] User groups, advantages, limitations, and "future improvements for limitations" all written.
- [ ] 2–3 polished UI screens are embedded in the doc with one paragraph of explanation each.

## Stretch

Pick one and note what you tried in your reflection:
- Add an interactive Figma prototype with click-through transitions between your three screens.
- Draw a system architecture diagram showing data flow between modules (Draw.io is great for this).
- Add a Business Model Canvas section with target market, revenue streams, and partner candidates.
- Compare two candidate algorithms side-by-side with mAP / accuracy / inference time you actually looked up.

## 🪞 Reflect on Your Work

Answer in 2-3 sentences each, in this README under your TODO commits. Your tutor reads these as part of grading.

1. **What did you learn that you didn't know before?** Name the most surprising thing — a constraint you discovered, a user you didn't expect to matter, a tool that turned out to be wrong for the job.
2. **How did you collaborate with AI?** If you used Claude / ChatGPT / Cursor / Copilot, what part of the work did *you* contribute — the prompt, the verification, the design decision, the writing voice? If you didn't use AI, what was the hardest thing to figure out alone?
3. **How do you know your proposal works?** Describe one specific thing you did to test it — a friend you asked to read it, a tutor checkpoint you passed, a user-flow walkthrough you did with the mockups.

> AI is a great collaborator. Owning your thinking, verifying the output, and explaining your design choices is what *learning* looks like in this course.
